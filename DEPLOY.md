# Family Hub — Production Deploy Guide

Stack: **React frontend** (Vercel) → **Express API** (Render) → **MongoDB Atlas** (M0), with **Google OAuth**.

Repo layout:
```
family-hub/
├── src/           # React app (CRA) — lives at repo root
├── server/        # Express API
└── vercel.json    # forwards /api/* from Vercel to the Render API
```

---

## Part 1 — MongoDB Atlas (database)

1. In your M0 cluster → **Network Access** → add IP `0.0.0.0/0` (allow from anywhere). Render doesn't give a static outbound IP, so you can't whitelist a single address. The connection string + credentials are your real security boundary.
2. **Database Access** → create a dedicated app user (not your admin login) with `readWrite` on the `prod` database only.
3. Grab the connection string — the direct (non-SRV) format this app uses:
   ```
   mongodb://<user>:<pass>@host1:27017,host2:27017,host3:27017/prod?ssl=true&replicaSet=...&authSource=admin&retryWrites=true&w=majority
   ```
   Keep that for the Render env var below — don't commit it.

## Part 2 — Render (Express backend)

### 2a. `render.yaml` (blueprint, lives at repo root)

```yaml
services:
  - type: web
    name: family-hub-api
    runtime: node
    rootDir: server
    plan: starter
    buildCommand: npm install
    startCommand: npm start
    healthCheckPath: /api/health
    envVars:
      - key: NODE_ENV
        value: production
      - key: NODE_VERSION
        value: "22"          # the auth route uses the built-in fetch (Node 18+)
      - key: JWT_SECRET
        generateValue: true
      - key: MONGODB_URI
        sync: false          # set in the Render dashboard, never in git
      - key: GOOGLE_CLIENT_ID
        sync: false          # same value as REACT_APP_GOOGLE_CLIENT_ID
      - key: CLIENT_ORIGIN
        sync: false          # your Vercel URL, e.g. https://family-hub.vercel.app
```

This file is already in the repo root as `render.yaml`.

`sync: false` means "I'll type the value in the Render dashboard, not in git." After first deploy, set `MONGODB_URI`, `CLIENT_ORIGIN` and `GOOGLE_CLIENT_ID` under **Environment** in the dashboard. `JWT_SECRET` is auto-generated by Render. The server refuses to start if `JWT_SECRET` or `GOOGLE_CLIENT_ID` is missing.

`GOOGLE_CLIENT_ID` is how the server confirms a Google sign-in token was issued to *this* app and not some other OAuth app. If it doesn't match the frontend's client ID, every sign-in is rejected.

### 2b. CORS

The server already reads `CLIENT_ORIGIN` from env:

```javascript
app.use(cors({ origin: process.env.CLIENT_ORIGIN || 'http://localhost:3000' }));
```

No `credentials: true` is needed — auth uses JWT in the `Authorization` header (not cookies), so there are no cross-origin cookie issues. Because Vercel proxies `/api/*` (see Part 3), the browser only ever talks to one origin anyway.

### 2c. Health route

Already implemented in `server/index.js`:

```javascript
app.get('/api/health', (_, res) => res.json({ ok: true }));
```

### 2d. Deploy

Render dashboard → **New +** → **Blueprint** → point at your repo → it reads `render.yaml`. First build takes a few minutes. Your API lands at `https://family-hub-api.onrender.com`.

## Part 3 — Vercel (React frontend)

### 3a. Import the project

Vercel dashboard → **Add New… → Project** → import the GitHub repo. It auto-detects Create React App; leave the defaults (build command `npm run build`, output directory `build`, root directory blank).

### 3b. `vercel.json` (already in the repo root)

```json
{
  "rewrites": [
    { "source": "/api/:path*", "destination": "https://family-hub-api.onrender.com/api/:path*" },
    { "source": "/(.*)", "destination": "/index.html" }
  ]
}
```

- **First rule** — the frontend calls relative `/api/...` URLs. In dev the CRA `"proxy"` setting handles that; it does nothing in a production build. This rule forwards them to Render, so there are no frontend code changes and no browser-side CORS.
- **Second rule** — makes deep links like `/calendar` load the app instead of a 404 (React Router handles the route).
- **Edit the Render hostname** in the first rule if your service isn't named `family-hub-api`.

### 3c. Environment variables

Set this under **Project → Settings → Environment Variables** (Production). It's baked in at build time, so redeploy after changing it:

| Variable | Value |
|---|---|
| `REACT_APP_GOOGLE_CLIENT_ID` | Your OAuth client ID |

Everything prefixed `REACT_APP_` ships in the public JS bundle. Every other setting (calendar ID, client secret, push keys) lives on Render.

### 3d. Deploy

Vercel builds on every push to `main` and gives you `https://<project>.vercel.app`. Copy that URL into Render's `CLIENT_ORIGIN` env var (no trailing slash) and redeploy the API.

## Part 4 — Google OAuth

Sign-in uses Google's authorization-code flow: the browser is redirected to Google, Google redirects back to `/auth/callback`, and the API exchanges the code with the client secret. That gives the server a **refresh token**, so calendar access doesn't expire after an hour.

In **Google Cloud Console → APIs & Services → Credentials → your OAuth client**:

- **Authorized redirect URIs** — add both:
  - `https://<project>.vercel.app/auth/callback`
  - `http://localhost:3000/auth/callback`
- Copy the **client secret** into Render's `GOOGLE_CLIENT_SECRET` (and `server/.env` for local dev).
- **OAuth consent screen → Publishing status** must be **In production**. In *Testing*, Google expires refresh tokens after 7 days and everyone would be signed out weekly. The app can stay unverified (users click through the warning once).

The first sign-in after this change asks for consent again, which is expected.

## Part 5 — Render settings for the API

Use the **Starter** instance (about $7/month): it doesn't sleep, which the push notifications and instant app launches rely on. `render.yaml` already says `plan: starter`; for an existing service change it under **Settings → Instance Type**.

Set these in the Render dashboard in addition to the Part 2 variables (`server/.env.example` explains each):

| Variable | Value |
|---|---|
| `GOOGLE_CLIENT_SECRET` | From the OAuth client |
| `GOOGLE_CALENDAR_ID` | The shared family calendar's ID |
| `TOKEN_ENCRYPTION_KEY` | `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"` |
| `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` | `npx web-push generate-vapid-keys` (run once, keep them) |
| `VAPID_SUBJECT` | `mailto:` + your email |

The server refuses to start without `GOOGLE_CLIENT_SECRET` and a valid `TOKEN_ENCRYPTION_KEY`. Without the VAPID keys it runs but sends no notifications.

## Part 6 — Phones

1. Open the Vercel URL in **Safari → Share → Add to Home Screen**.
2. Open Family Hub **from the Home Screen icon** and sign in.
3. Tap **Turn on** in the banner on the To-dos tab and allow notifications.

iOS only allows web push for apps added to the Home Screen (iOS 16.4+). The icon badge shows your open to-dos. The session is stored in `localStorage` and lasts 60 days.
