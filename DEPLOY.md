# Family Hub — Production Deploy Guide

Stack: **React frontend** (Vercel) → **Express API** (Render) → **MongoDB Atlas** (M0), with **Google OAuth**.

Repo layout:
```
family-hub/
├── src/           # React app (CRA) — lives at repo root
├── server/        # Express API
└── vercel.json    # forwards /api/* from Vercel to the Render API
```

---

## Part 1 — MongoDB Atlas (database)

1. In your M0 cluster → **Network Access** → add IP `0.0.0.0/0` (allow from anywhere). Render's free tier doesn't give a static outbound IP, so you can't whitelist a single address. The connection string + credentials are your real security boundary.
2. **Database Access** → create a dedicated app user (not your admin login) with `readWrite` on the `prod` database only.
3. Grab the connection string — the direct (non-SRV) format this app uses:
   ```
   mongodb://<user>:<pass>@host1:27017,host2:27017,host3:27017/prod?ssl=true&replicaSet=...&authSource=admin&retryWrites=true&w=majority
   ```
   Keep that for the Render env var below — don't commit it.

## Part 2 — Render (Express backend)

### 2a. `render.yaml` (blueprint, lives at repo root)

```yaml
services:
  - type: web
    name: family-hub-api
    runtime: node
    rootDir: server
    plan: free
    buildCommand: npm install
    startCommand: npm start
    healthCheckPath: /api/health
    envVars:
      - key: NODE_ENV
        value: production
      - key: NODE_VERSION
        value: "22"          # the auth route uses the built-in fetch (Node 18+)
      - key: JWT_SECRET
        generateValue: true
      - key: MONGODB_URI
        sync: false          # set in the Render dashboard, never in git
      - key: GOOGLE_CLIENT_ID
        sync: false          # same value as REACT_APP_GOOGLE_CLIENT_ID
      - key: CLIENT_ORIGIN
        sync: false          # your Vercel URL, e.g. https://family-hub.vercel.app
```

This file is already in the repo root as `render.yaml`.

`sync: false` means "I'll type the value in the Render dashboard, not in git." After first deploy, set `MONGODB_URI`, `CLIENT_ORIGIN` and `GOOGLE_CLIENT_ID` under **Environment** in the dashboard. `JWT_SECRET` is auto-generated by Render. The server refuses to start if `JWT_SECRET` or `GOOGLE_CLIENT_ID` is missing.

`GOOGLE_CLIENT_ID` is how the server confirms a Google sign-in token was issued to *this* app and not some other OAuth app. If it doesn't match the frontend's client ID, every sign-in is rejected.

### 2b. CORS

The server already reads `CLIENT_ORIGIN` from env:

```javascript
app.use(cors({ origin: process.env.CLIENT_ORIGIN || 'http://localhost:3000' }));
```

No `credentials: true` is needed — auth uses JWT in the `Authorization` header (not cookies), so there are no cross-origin cookie issues. Because Vercel proxies `/api/*` (see Part 3), the browser only ever talks to one origin anyway.

### 2c. Health route

Already implemented in `server/index.js`:

```javascript
app.get('/api/health', (_, res) => res.json({ ok: true }));
```

### 2d. Deploy

Render dashboard → **New +** → **Blueprint** → point at your repo → it reads `render.yaml`. First build takes a few minutes. Your API lands at `https://family-hub-api.onrender.com`.

## Part 3 — Vercel (React frontend)

### 3a. Import the project

Vercel dashboard → **Add New… → Project** → import the GitHub repo. It auto-detects Create React App; leave the defaults (build command `npm run build`, output directory `build`, root directory blank).

### 3b. `vercel.json` (already in the repo root)

```json
{
  "rewrites": [
    { "source": "/api/:path*", "destination": "https://family-hub-api.onrender.com/api/:path*" },
    { "source": "/(.*)", "destination": "/index.html" }
  ]
}
```

- **First rule** — the frontend calls relative `/api/...` URLs. In dev the CRA `"proxy"` setting handles that; it does nothing in a production build. This rule forwards them to Render, so there are no frontend code changes and no browser-side CORS.
- **Second rule** — makes deep links like `/calendar` load the app instead of a 404 (React Router handles the route).
- **Edit the Render hostname** in the first rule if your service isn't named `family-hub-api`.

### 3c. Environment variables

Set these under **Project → Settings → Environment Variables** (Production). They're baked in at build time, so redeploy after changing any:

| Variable | Value |
|---|---|
| `REACT_APP_GOOGLE_CLIENT_ID` | Your OAuth client ID |
| `REACT_APP_GOOGLE_PLACES_KEY` | Google Places API key |
| `REACT_APP_GOOGLE_CALENDAR_ID` | Shared family calendar ID |

Everything prefixed `REACT_APP_` ships in the public JS bundle. Before going live, restrict the Places key in **Google Cloud Console → Credentials → your API key**: under *Application restrictions* choose **Websites** and add `https://<project>.vercel.app/*` (plus `http://localhost:3000/*` for dev), and under *API restrictions* allow only **Places API (New)**. Otherwise anyone who copies the key from the bundle can run up your bill.

### 3d. Deploy

Vercel builds on every push to `main` and gives you `https://<project>.vercel.app`. Copy that URL into Render's `CLIENT_ORIGIN` env var (no trailing slash) and redeploy the API.

## Part 4 — Google OAuth

In **Google Cloud Console → Credentials → your OAuth client**, the only thing that needs updating for production is:

- **Authorized JavaScript origins** — add:
  `https://<project>.vercel.app`

No server-side callback URI is needed. The app uses Google Identity Services' client-side token flow (`useGoogleLogin` from `@react-oauth/google`), which gets the `access_token` directly in the browser and POSTs it to `/api/auth/google` for allowlist verification.

Keep your `http://localhost:3000` entry so local dev still works — Google allows multiple origins.

## Part 5 — The cold-start workaround

Render free web services sleep after 15 min idle → next request takes 30–60s. Two options:

- **Accept it.** For a family app opened a few times a day, a slow first load is livable and costs nothing.
- **Keep it warm** with a free external pinger hitting `/api/health` every ~14 min:
  - **UptimeRobot** (free, 5-min intervals) — easiest, no code.
  - Or a **GitHub Actions cron**:

```yaml
# .github/workflows/keepalive.yml
name: keepalive
on:
  schedule:
    - cron: "*/14 * * * *"
jobs:
  ping:
    runs-on: ubuntu-latest
    steps:
      - run: curl -s https://family-hub-api.onrender.com/api/health
```

## Part 6 — Phones

The app is responsive: below 768px the top links become a bottom tab bar, and the calendar week becomes a day-by-day list. To install it on an iPhone: open the Vercel URL in **Safari → Share → Add to Home Screen**.

Sign-in lives in `sessionStorage` and Google access tokens last ~1 hour, so expect to sign in again after closing the app.

- [ ] Atlas network access set to `0.0.0.0/0`, dedicated app user created
- [ ] Render env vars set in dashboard: `MONGODB_URI`, `CLIENT_ORIGIN`, `GOOGLE_CLIENT_ID` (must equal the frontend's client ID)
- [ ] Places API key restricted to your Vercel domain + Places API only
- [ ] `CLIENT_ORIGIN` on Render = exact Vercel URL (no trailing slash)
- [ ] `vercel.json` rewrite points at your real Render hostname
- [ ] All `REACT_APP_*` env vars set in Vercel → Environment Variables
- [ ] Google OAuth **Authorized JavaScript origins** updated with the Vercel URL
- [ ] Tested: sign-in works, calendar reads/writes to shared Google Calendar
- [ ] Tested on a phone: bottom tab bar shows, Add to Home Screen works
