# Family Hub — Production Deploy Guide

Stack: **React frontend** (Cloudflare Pages) → **Express API** (Render) → **MongoDB Atlas** (M0), with **Google OAuth**.

Repo layout:
```
family-hub/
├── src/           # React app (CRA) — lives at repo root
└── server/        # Express API
```

---

## Part 1 — MongoDB Atlas (database)

1. In your M0 cluster → **Network Access** → add IP `0.0.0.0/0` (allow from anywhere). Render's free tier doesn't give a static outbound IP, so you can't whitelist a single address. The connection string + credentials are your real security boundary.
2. **Database Access** → create a dedicated app user (not your admin login) with `readWrite` on the `prod` database only.
3. Grab the connection string — the direct (non-SRV) format this app uses:
   ```
   mongodb://<user>:<pass>@host1:27017,host2:27017,host3:27017/prod?ssl=true&replicaSet=...&authSource=admin&retryWrites=true&w=majority
   ```
   Keep that for the Render env var below — don't commit it.

## Part 2 — Render (Express backend)

### 2a. `render.yaml` (blueprint, lives at repo root)

```yaml
services:
  - type: web
    name: family-hub-api
    runtime: node
    rootDir: server
    plan: free
    buildCommand: npm install
    startCommand: npm start
    healthCheckPath: /api/health
    envVars:
      - key: NODE_ENV
        value: production
      - key: MONGODB_URI
        sync: false
      - key: JWT_SECRET
        generateValue: true
      - key: CLIENT_ORIGIN
        sync: false        # your Cloudflare Pages URL, e.g. https://family-hub.pages.dev
```

`sync: false` means "I'll type the value in the Render dashboard, not in git." After first deploy, set `MONGODB_URI` and `CLIENT_ORIGIN` under **Environment** in the dashboard. `JWT_SECRET` is auto-generated by Render.

### 2b. CORS

The server already reads `CLIENT_ORIGIN` from env:

```javascript
app.use(cors({ origin: process.env.CLIENT_ORIGIN || 'http://localhost:3000' }));
```

No `credentials: true` is needed — auth uses JWT in the `Authorization` header (not cookies), so there are no cross-origin cookie issues.

### 2c. Health route

Already implemented in `server/index.js`:

```javascript
app.get('/api/health', (_, res) => res.json({ ok: true }));
```

### 2d. Deploy

Render dashboard → **New +** → **Blueprint** → point at your repo → it reads `render.yaml`. First build takes a few minutes. Your API lands at `https://family-hub-api.onrender.com`.

## Part 3 — Cloudflare Pages (React frontend)

### 3a. Build settings (in the Pages dashboard)

| Setting | Value |
|---|---|
| Root directory | *(leave blank — React is at repo root)* |
| Build command | `npm run build` |
| Output directory | `build` |

### 3b. Environment variables

Set these under **Pages → Settings → Environment variables → Production**:

| Variable | Value |
|---|---|
| `REACT_APP_GOOGLE_CLIENT_ID` | Your OAuth client ID |
| `REACT_APP_SPREADSHEET_ID` | Google Sheets ID |
| `REACT_APP_FINNHUB_API_KEY` | Finnhub key |
| `REACT_APP_GOOGLE_PLACES_KEY` | Google Places API key |
| `REACT_APP_GOOGLE_CALENDAR_ID` | Shared family calendar ID |
| `REACT_APP_FINANCE_PIN` | 4-digit PIN (optional) |

The frontend talks to the backend via fetch with the JWT in the `Authorization` header — no `credentials: "include"` needed.

### 3c. Deploy

Connect the GitHub repo in Cloudflare Pages → it builds on every push to `main` and gives you `https://family-hub.pages.dev`. Copy this URL back into Render's `CLIENT_ORIGIN` env var and redeploy the API so CORS matches.

## Part 4 — Google OAuth

In **Google Cloud Console → Credentials → your OAuth client**, the only thing that needs updating for production is:

- **Authorized JavaScript origins** — add:
  `https://family-hub.pages.dev`

No server-side callback URI is needed. The app uses Google Identity Services' client-side token flow (`useGoogleLogin` from `@react-oauth/google`), which gets the `access_token` directly in the browser and POSTs it to `/api/auth/google` for allowlist verification.

Keep your `http://localhost:3000` entry so local dev still works — Google allows multiple origins.

## Part 5 — The cold-start workaround

Render free web services sleep after 15 min idle → next request takes 30–60s. Two options:

- **Accept it.** For a family app opened a few times a day, a slow first load is livable and costs nothing.
- **Keep it warm** with a free external pinger hitting `/api/health` every ~14 min:
  - **UptimeRobot** (free, 5-min intervals) — easiest, no code.
  - Or a **GitHub Actions cron**:

```yaml
# .github/workflows/keepalive.yml
name: keepalive
on:
  schedule:
    - cron: "*/14 * * * *"
jobs:
  ping:
    runs-on: ubuntu-latest
    steps:
      - run: curl -s https://family-hub-api.onrender.com/api/health
```
